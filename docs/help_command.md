# Команда /help: RAG по документации проекта + git-контекст

## Что это

Отдельный режим чата: сообщение, начинающееся с `/help`, отвечает на
вопросы о самом проекте — по его документации (README, `docs/*.md`,
конфиги) с git-контекстом (текущая ветка). Обычный диалог при этом не
затрагивается: история, память задачи (task state) и FSM задач остаются
без изменений.

```
/help как устроена архитектура?
```

## Схема обработки

```
Пользователь: /help <вопрос>
    ↓
1. parse_command (app/chat_handler.py) → ("help", "<вопрос>")
    ↓
2. ProjectRAG.search_chunks_async — RAG-поиск по коллекции
   project_docs (Chroma, cosine; app/rag/project_rag.py)
    ↓
3. MCPClient.call_tool("get_current_branch", {"repo_path": …}) —
   stdio-сервер my_git_server.py (ветка; detached HEAD → хеш)
    ↓
4. Промпт: [инструкция «ассистент разработчика»] +
   [Документация проекта: чанки] + [Git-контекст: ветка] + [Вопрос]
   — уходит ядру через set_rag_context (в копию запроса)
    ↓
5. Ответ ИЗОЛИРОВАННОГО ядра (без хранилища, аналог answer_once):
   история основного чата и память задачи не трогаются
    ↓
6. Ответ + источники (панель под ответом) + git-контекст
```

## Отказоустойчивость

| Отказ | Поведение |
|---|---|
| Git MCP недоступен (сервер не поднялся, таймаут) | Пометка «Git-контекст недоступен: …» в промпте, ответ всё равно генерируется (`git_error` в результате) |
| Ollama недоступна (эмбеддинги) | В промпт уходит пометка «документация недоступна», ответ из общих знаний (`rag_error`) |
| `/help` без вопроса | Подсказка по использованию, LLM и MCP не вызываются |
| Пайплайн не настроен (`help_pipeline=None`) | Сообщение уходит обычным ходом чата (деградация) |

## Индексация документации

Вкладка **⚙️ Настройки → 🗂 Документация проекта (/help)**:

* поле **«Путь к проекту»** (по умолчанию — корень самого приложения);
* кнопка **«Проиндексировать документацию проекта»**.

Что индексируется (код `*.py` — нет):

* README в корне (`README.md` / `readme.md` / `README.MD`);
* `docs/**/*.md` — рекурсивно;
* конфиги в корне: `requirements.txt`, `pyproject.toml`, `setup.py`,
  `docker-compose.yml`.

Chunking — structure-aware (по заголовкам `#/##/###`, 500/50).
Коллекция — **отдельная** (`project_docs` в том же Chroma, что и личная
`knowledge_base`; базы не смешиваются). Переиндексация перезаписывает
коллекцию целиком. Выбранный путь сохраняется в app_state (SQLite,
ключ `project_docs_path`) и переживает перезапуск.

## Автодополнение

При вводе `/` в поле чата (пока сообщение короче 10 символов) под
полем появляется подсказка «/help — вопросы о проекте»; клик
подставляет команду в поле. Панель прячется при продолжении ввода и
при отправке.

## Компоненты

| Файл | Назначение |
|---|---|
| `app/rag/project_rag.py` | `ProjectRAG`: сбор файлов, индексация, поиск (коллекция `project_docs`) |
| `app/help_pipeline.py` | `HelpPipeline` (RAG + git MCP + промпт + LLM), `build_git_mcp_client`, `parse_branch_text` |
| `app/chat_handler.py` | `parse_command`, диспетчер `/help` в `handle_message` |
| `my_git_server.py` | инструмент `get_current_branch` (git MCP, stdio) |
| `app/ui/chat_view.py` | автодополнение «/», показ git-контекста в ответе |
| `app/ui/project_docs_view.py` | панель «Документация проекта» в настройках |
| `app/agent.py` | `isolated_core()` — изолированное ядро для /help |
| `app/main.py` | проводка: ProjectRAG + HelpPipeline + путь из app_state |
