# Команда /support: AI-ассистент поддержки с CRM MCP и RAG (ai_1_34)

`/support` — отдельный режим чата для ответов пользователям службы
поддержки: вопрос ищется в FAQ (`support_faq`), параллельно через
собственный CRM MCP-сервер подтягивается контекст пользователя
(тикеты, статус), и всё это уходит в LLM одним промптом.

## Схема обработки

```
Пользователь: /support Почему не работает авторизация?
  → parse_command перехватывает «/support …» (граница слова)
  → user_id — из выпадающего списка в шапке чата (НЕ хардкод)
  → 1. RAG-поиск по коллекции support_faq (top_k 3)
    2. MCP-вызов get_user_context(user_id) → crm_server.py:8004
  → промпт: [инструкция] + [Контекст пользователя] + [FAQ] + [Вопрос]
  → ответ изолированного ядра + источники под ответом
  → CRM недоступен → фолбэк: ответ только по FAQ (пометка в UI)
```

Режим изолированный (как /help): ход идёт на отдельном ядре без
хранилища — история основного чата, память задачи (task state) и FSM
задач не затрагиваются.

## Компоненты

| Компонент | Файл | Что делает |
|---|---|---|
| CRM MCP-сервер | `crm_server.py` | FastMCP, Streamable HTTP, порт 8004; данные — `crm_data.json` |
| Данные CRM | `crm_data.json` | Пользователи (id/name/email/status) + тикеты (id/subject/status/priority) |
| Лаунчер | `src/crm_launcher.py` | Автозапуск в отдельном окне вместе с приложением |
| RAG поддержки | `app/rag/support_rag.py` | Коллекция `support_faq` (Chroma, cosine), *.md рекурсивно, батч-эмбеддинги |
| Пайплайн | `app/support_pipeline.py` | CRM + FAQ → промпт → изолированное ядро; фолбэки |
| Диспетчер | `app/chat_handler.py` | `parse_command` различает /support и /help; user_id через `get_support_user_id` |
| UI чата | `app/ui/chat_view.py` | Автодополнение «/», выпадающий список «Пользователь (для /support)» |
| Панель в Настройках | `app/ui/support_docs_view.py` | Путь к папке FAQ + индексация в support_faq |

Инструменты CRM-сервера: `get_user_context(user_id)` (основной),
`get_user(user_id)`, `get_user_tickets(user_id)`, `list_users()`
(заполняет выпадающий список в UI).

## Настройки

Переменные окружения (`.env`):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `CRM_ENABLED` | `true` | автозапуск CRM-сервера и вызовы из /support |
| `CRM_SERVER_HOST` | `127.0.0.1` | адрес привязки (хостить в интернете запрещено) |
| `CRM_SERVER_PORT` | `8004` | порт MCP-эндпоинта `http://…/mcp` |
| `SUPPORT_DOCS_PATH` | `support_docs/` | папка с FAQ (`*.md`); относительный путь — от корня проекта |

Путь к FAQ также выбирается в Настройках (панель «🛟 Поддержка
(/support)») и сохраняется в app_state (ключ `support_docs_path`).

## Индексация FAQ

- при старте приложения коллекция `support_faq` наполняется автоматически,
  если пуста (фоновая задача, старт не блокируется);
- кнопкой «Проиндексировать FAQ поддержки» в Настройках — в любой момент;
- эмбеддинги генерируются батчами по 64 (один POST /api/embed на всё
  не масштабируется — урок ai_1_33); недоступная Ollama не очищает
  старую коллекцию.

## Фолбэки (ответ не ломается)

| Ситуация | Поведение |
|---|---|
| CRM-сервер не поднят / таймаут | пометка «Контекст пользователя недоступен» в промпте, `crm_available=False`, предупреждение под ответом |
| Пользователь не выбран в списке | CRM не вызывается (`NO_USER_MARKER`), ответ по FAQ |
| Пользователя нет в CRM | текст ошибки сервера уходит в промпт как пометка |
| Ollama недоступна (нет RAG) | пометка вместо FAQ, ответ по CRM-контексту |
| Пайплайн не настроен | `/support …` уходит обычным ходом чата (деградация) |

## Запуск вручную

```bash
python crm_server.py --port 8004          # CRM на своём порту
python crm_server.py --data my_crm.json   # свой JSON вместо crm_data.json
```
