# Возможности приложения

Обзор функциональности DeepSeek Chat.

## Диалог и память

Приложение ведёт диалог с моделью DeepSeek через API, совместимое с OpenAI SDK. История сохраняется в SQLite и переживает перезапуск. Краткосрочная память держит последние сообщения, рабочая память — ключевые факты текущего диалога, долговременная память накапливает сведения о пользователе между сессиями и подставляет их в системный промпт.

## Профили пользователей

Каждый профиль хранит имя, роль, тон общения и собственные настройки модели: температуру, лимит токенов и модель. Активный профиль выбирается в настройках; его параметры перекрывают значения из .env. Переключение профиля не очищает историю.

## Задачи с конечным автоматом

Многошаговые задачи проходят стадии: планирование, выполнение шагов, проверка результата, завершение. Переходы разрешены только по явной матрице переходов; недопустимый переход отклоняется с ошибкой для статус-бара. Задача переживает перезапуск приложения: состояние хранится в data/tasks.db.

## Инварианты

Жёсткие правила «что можно делать» задаются в SQLite: категории, формулировки, строгость. Правила добавляются блоком в системный промпт, а ответы проходят пост-проверку отдельным вызовом модели: при нарушении ответ перегенерируется до лимита попыток, после чего показывается предупреждение.

## Контекстные стратегии

sliding_window держит в запросе последние N сообщений. sticky_facts извлекает факты и обновляет их после каждого хода. branching хранит диалог деревом веток с независимыми артефактами. Стратегия выбирается в настройках профиля.

## Токены и стоимость

Счётчик токенов использует tiktoken с оценкой эвристикой как резервом. Для каждой пары «вопрос-ответ» считаются prompt/completion/total токены, кэш-попадания и стоимость в долларах по ценам модели; итоги сессии показываются в интерфейсе.

## MCP-инструменты

Model Context Protocol подключает внешние возможности: напоминания с планировщиком и SSE-уведомлениями, поиск новостей по RSS с суммаризацией и сохранением в файл, определение города по IP и прогноз погоды через цепочку гео → погода. LLM сама строит цепочки вызовов в agentic loop; недоступный сервер не ломает диалог, а упавший поднимается автоматически.
