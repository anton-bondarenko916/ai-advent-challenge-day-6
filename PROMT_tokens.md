# ПРОМПТ ДЛЯ CODE ASSISTANT: ПОДСЧЁТ ТОКЕНОВ В DEEPSEEK CHAT

## ЦЕЛЬ ЗАДАЧИ
Доработать существующее приложение **DeepSeek Chat** (Python 3.9+ / Tkinter /
DeepSeek API с сохранением контекста в SQLite) — добавить **подсчёт токенов**:

1. **для текущего запроса** — сколько токенов ушло в API на последний запрос;
2. **для всей истории диалога** — размер текущего контекста (то, что уйдёт в
   следующий запрос) И суммарные траты за всю сессию (включая вытесненные из окна);
3. **для ответа модели** — сколько токенов сгенерировала модель.

Плюс — отображение статистики в UI и **оценка стоимости в USD**.
Изменять существующие файлы **на месте**, не переписывать проект; не ломать
текущий функционал и существующие тесты.

## ИСХОДНОЕ СОСТОЯНИЕ ПРОЕКТА (учесть, не ломать)
```
deepseek-chat-app/
├── main.py            # load_config → ContextStore → DeepSeekAgent → ChatApplication
├── src/
│   ├── config.py      # DEFAULTS + приведение типов; PROJECT_ROOT, ENV_PATH
│   ├── agent.py       # DeepSeekAgent: RLock, история (system+диалог), лимит 50,
│   │                  # mock-режим, персист через ContextStore, close()
│   ├── storage.py     # ContextStore (sqlite3): messages + meta(JSON params, schema_version="1")
│   ├── ui.py          # ChatApplication: статус-бар (слева статус, справа model/tokens/time),
│   │                  # панель параметров (2 ряда, height=110), worker-поток + queue
│   └── utils.py       # валидаторы, format_tokens(), get_logger, humanize_api_error
└── tests/             # 36 офлайн-тестов (unittest), включая tests/test_persistence.py
```
Ключевые факты:
- `send_message()` возвращает `{text, model, tokens, response_time, finish_reason,
  error, timestamp}`, где `tokens = {prompt_tokens, completion_tokens, total_tokens}`
  (значения из `response.usage`, либо `None`); ошибок не пробрасывает;
- после успешного обмена вызывается `_persist()` → `ContextStore.save_state(messages, params)`;
- при старте `_load_context()` восстанавливает историю и параметры (в mock-режиме
  хранилище игнорируется: ни чтение, ни запись);
- `update_config()` поддерживает смену system_prompt (сбрасывает историю) и параметров;
- `clear_history()` очищает историю в памяти и на диске;
- UI: `_insert_message()` рисует сообщения из `agent.history`; `_on_result()` заполняет
  правую часть статус-бара через `utils.format_tokens()`; `_set_controls_enabled()`
  блокирует виджеты на время запроса;
- среда разработки: **нет доступа к PyPI** (пакеты не устанавливаются), Python 3.13,
  установлен `openai` 3.6.0; доступ к внешней сети из кода отсутствует.

## РЕШЕНИЯ, СОГЛАСОВАННЫЕ С ЗАКАЗЧИКОМ (реализовать именно так)
1. **Гибридный подсчёт**: точные значения из `response.usage` для реального
   запроса/ответа + локальная оценка для истории и запроса до отправки.
2. **Два показателя истории**: (а) токены текущего контекста в памяти
   (system + сообщения окна ≤50) и (б) суммарные траты за сессию
   (prompt/completion/total, число запросов), накапливаемые по данным API.
3. **Локальная оценка — через `tiktoken`** (добавить в requirements.txt), но с
   обязательным **graceful degradation**: если пакет не установлен или
   невозможна загрузка BPE-файла (офлайн), используется встроенная эвристика,
   один раз пишется предупреждение в лог; приложение продолжает работать.
4. **Отображение**: расширенный статус-бар + компактный блок «Токены» на панели
   параметров (запрос / ответ / контекст / сессия / стоимость).
5. **Накопленная статистика сохраняется в SQLite** и восстанавливается при
   перезапуске (вместе с историей и параметрами).
6. **Контракт агента расширяется обратносовместимо**: существующий
   `result["tokens"]` дополняется полями; старые ключи и поведение не меняются;
   добавляются публичные методы/свойства для UI.
7. **Оценка стоимости в USD** по ценам из `.env` (цена за 1M input/output токенов,
   опционально переопределение по модели). Если цены не заданы — стоимость
   не показывается («—»), ничего не хардкодим.

## ТРЕБОВАНИЯ К РЕАЛИЗАЦИИ

### 1. Новый модуль `src/tokens.py` — счётчик токенов
Класс/функции (имена на усмотрение, но модуль — `src/tokens.py`):
- **Абстракция счётчика** с двумя реализациями и авто-выбором:
  - `TiktokenCounter`: использует `tiktoken`; кодировку выбирать так:
    `tiktoken.encoding_for_model(self.model)` → при неудаче `tiktoken.get_encoding(encoding_name)`
    (по умолчанию `cl100k_base`); инстанс кодировки **кэшировать** (создавать один раз);
  - `HeuristicCounter` (stdlib): приближённая формула, учитывающая кириллицу и латиницу
    (например, `ceil(cyrillic_chars / 2.5 + latin_chars / 4) + words*0.2` — точную формулу
    выбрать обоснованно и задокументировать), обязательно возвращающая 0 для пустой строки;
- **Chat-overhead**: оценка сообщений должна учитывать формат чата
  (`~4 токена на сообщение + 3` служебных — как в OpenAI cookbook), чтобы оценка
  контекста была ближе к `usage.prompt_tokens`;
- Публичный интерфейс (примерный):
  - `count_text(text: str) -> int`
  - `count_messages(messages: list[dict]) -> int` (с overhead)
  - `name` / `is_exact` — какой движок активен (для UI-пометки «≈»);
- **Никаких сетевых вызовов**: любая ошибка `tiktoken` (ImportError, ошибка загрузки
  BPE, отсутствие кэша) перехватывается, логируется один раз и переключает на эвристику;
- Поддержать переменную окружения `TIKTOKEN_CACHE_DIR` (прокидывать, если задана);
- Модуль не должен импортировать tkinter/openai.

### 2. `src/agent.py` — учёт токенов
- **Параметры `__init__`**: `token_counter=None` (по умолчанию создаётся
  `src/tokens.py` для текущей модели), `prices=None` (словарь цен, см. п. 4).
- **Внутреннее состояние** (под существующим RLock):
  - последний обмен: `{request_tokens, response_tokens, total_tokens, estimated, cost_usd}`;
  - накопленная статистика сессии: `{prompt_tokens, completion_tokens, total_tokens,
    requests, cost_usd}`;
  - контекст истории считается на лету (не хранится).
- **Обновление после успешного обмена** (в `send_message`, рядом с `_persist()`):
  - если API вернул `usage`: прибавить точные `prompt_tokens`/`completion_tokens` к
    сессионным суммам, `requests += 1`, посчитать стоимость по ценам, пометить
    `estimated=False`;
  - если `usage` отсутствует (`tokens is None`): использовать локальную оценку
    (запрос = `count_messages` отправленной истории ДО добавления ответа,
    ответ = `count_text` ответа), пометить `estimated=True`; сессионные суммы
    обновлять оценкой с пометкой (в отчёте явно разделять точные и оценочные);
  - при ошибке API (откат сообщения) счётчики **не меняются**.
- **Расширение результата `send_message()`** (обратносовместимо, старые ключи сохранить):
  ```python
  "tokens": {
      # было:
      "prompt_tokens": int | None,
      "completion_tokens": int | None,
      "total_tokens": int | None,
      # стало (новые ключи):
      "estimated": bool,             # True, если значения получены оценкой
      "context_tokens": int,         # оценка всего контекста истории в окне
      "session_total_tokens": int,   # накопленный total за сессию
      "cost_usd": float | None,      # стоимость последнего обмена (None без цен)
      "session_cost_usd": float | None,
      "cache_hit_tokens": int | None,     # если API вернул prompt_cache_hit_tokens
      "cache_miss_tokens": int | None,    # если API вернул prompt_cache_miss_tokens
  }
  ```
- **Новые публичные методы/свойства**:
  - `get_token_stats() -> dict` — полная статистика для UI:
    `{"request": {...}, "response": {...}, "context": {"tokens", "messages", "estimated"},
      "session": {...}, "counter": "tiktoken:cl100k_base" | "heuristic"}`;
  - `count_tokens(text) -> int` и `count_history_tokens() -> int` (оценка контекста);
  - свойство `session_stats` (копия, только чтение).
- **Персист**: при `_persist()` передавать в хранилище и статистику сессии
  (см. п. 3); при загрузке контекста (`_load_context`) **восстанавливать**
  накопленную статистику; при `clear_history()` — решить и задокументировать:
  **сбрасывать сессионные счётчики вместе с историей** (согласованно с очисткой на
  диске), а последний обмен очищать.
- Все новые операции — под RLock; ошибки счётчика/цен не должны ломать
  `send_message` (при сбое — оценка 0/None + запись в лог).

### 3. `src/storage.py` — хранение статистики
- Хранить статистику сессии в существующей таблице `meta` под ключом `stats`
  (JSON) — **без изменения структуры таблиц и без ломающей миграции**;
  старые БД (schema_version="1", без ключа `stats`) должны читаться: счётчики
  стартуют с нуля, история сохраняется.
- `save_state(messages, params, stats=None)`: если `stats` передан — записать;
  если `None` — не затирать прежнее значение (сохранить обратную совместимость
  существующих вызовов и тестов `test_persistence.py`).
- `load_state()` дополнительно возвращает `"stats": {...}` (пустой dict, если нет).
- `clear()` удаляет и ключ `stats`.
- Устойчивость: некорректный JSON в `stats` → пустая статистика + предупреждение.

### 5. `src/ui.py` — отображение
- **Панель параметров**: добавить компактный блок/ряд «Токены» (панель увеличить
  по высоте, например 110 → 150 px; остальные элементы не сломать) с полями:
  - `Запрос: <N>` (точное из API, иначе «≈N»);
  - `Ответ: <M>` (точное, иначе «≈M»);
  - `Контекст: <K>` (оценка, всегда с «≈», т.к. это будущий запрос);
  - `Сессия: <total> токенов · <cost> $` (или «—», если цены не заданы);
  - опционально: метка активного счётчика (`tiktoken` / «эвристика») мелким шрифтом.
- **Статус-бар**: правая часть — как сейчас (модель · токены последнего обмена ·
  время · finish_reason), плюс контекст, например:
  `deepseek-v4-flash · in: 12 · out: 34 · ctx: ≈120 · 0.85 с · stop`.
- **Обновление**: после каждого ответа (`_on_result`) и после действий, меняющих
  историю (очистка, смена системного промпта, загрузка контекста при старте) —
  вызывать `agent.get_token_stats()` и обновлять блок; при старте показывать
  восстановленные сессионные суммы.
- **Эстетика**: значения-оценки помечать «≈»; точные — без пометки; при `None` — «—»;
  использовать существующие цвета/шрифты (`COLORS`, `FONTS`), не ломать раскладку
  и resize.
- Никаких сетевых/тяжёлых вычислений в UI-потоке: счётчик кэшируется; подсчёт
  контекста (≤50 сообщений) выполняется в главном потоке допустимо, но не чаще,
  чем при обновлении статистики.

### 6. Тесты (офлайн, без сети и без установки пакетов)
Новый файл `tests/test_tokens.py` (unittest; временные файлы — внутри репозитория,
например `tests/tmp_tokens/`, системный TEMP в песочнице недоступен):
- эвристический счётчик: пустая строка → 0; монотонность; кириллица > 0;
- `count_messages` учитывает system/роли и overhead (значение > суммы текстов);
- `TiktokenCounter` тестировать **только если** `import tiktoken` и создание

- агент с подменённым `_call_api` (как в `test_persistence.py`):
  - при наличии `usage` сессионные суммы растут точно (`estimated=False`);
  - при `usage=None` суммы растут оценкой (`estimated=True`), `cost_usd is None`
    без цен;
  - ошибка API (исключение) не меняет счётчики;

- стоимость: при заданных ценах `cost_usd` считается по формуле

- персист: счётчики сохраняются и восстанавливаются после «перезапуска»

- БД старого формата (schema_version="1" без ключа `stats`) читается корректно;
- существующие 36 тестов остаются зелёными (в т.ч. `test_persistence.py` —
